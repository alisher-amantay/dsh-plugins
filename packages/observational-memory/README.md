# @alisher-amantay/dsh-observational-memory

English | [中文](README.zh.md)

This plugin is a port of [pi-observational-memory](https://github.com/elpapi42/pi-observational-memory).

Session-local observational memory for DeepSeek Harness. The Cordis service extends the basic compaction engine, records source-backed observations and reflections, supplies `/memory-status` and `/memory-view`, and registers `observational_memory_recall` for exact evidence paging.

Mount it in an agent preset inside the same isolated `compaction` and `toolResultPruner` realm as the compact command and result pruner. Do not mount it beside another compaction provider.

The plugin writes its ledger as `plugin:observational-memory/…` plugin records, which carry `ignorable: true`. A Harness installation that does not load this package can reconstruct the ordinary conversation while omitting the optional memory projection. Sessions written before the V4 Session format store the same records as `observational-memory/…` events; the V3-to-V4 migration renames them into the `plugin:` namespace, so the projection reads both generations. Deterministic compacted summaries remain ordinary first-party compaction events.

Observer work is token-clocked: a completed step or turn triggers it, `observeAfterTokens` gates the first chunk, and one trigger drains up to four observer chunks, so coverage keeps up inside a long turn. A trigger that arrives while a worker is already running is queued rather than dropped. A source message larger than the observer input — a compaction checkpoint or a large tool result — is sent as a head-and-tail excerpt instead of aborting the coverage watermark. If that call still fails, the oldest message is recorded as skipped and coverage advances through it, so one unanswerable checkpoint cannot freeze the ledger. Reflection and the dropper also run when the active pool exceeds `observationsPoolTargetTokens`, even while observation is still catching up. Compaction does not ask a model to rewrite the transcript. The summary is the rendered memory, trimmed to the newest covered observations that fit `observationsPoolTargetTokens` and still leave the framed checkpoint smaller than the span it replaces. Before that summary is written, the active pool is trimmed to the same target, dropping oldest low-relevance observations first, so a backlog cannot be pasted back into the context. Pressure compaction uses Pi's 0.68 window ratio rather than waiting until the window edge. Overflow recovery keeps a recent tail and replaces only the older span, instead of shadowing the whole surface. An empty ledger still falls back to the model summarizer. Idle compaction first drains a bounded observer backlog so the rendered memory can cover the range.

A deployment mounts this provider from the preset it wants memory in: `@alisher-amantay/dsh-observational-memory-bundle` supplies its own Standard, PTC, and Cordis presets, and this checkout's shipped Standard, PTC, and Cordis presets mount it directly. Minimal stays unchanged.
